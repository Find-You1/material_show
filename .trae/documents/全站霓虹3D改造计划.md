# 全站 UI 改造 v2：冷灰墨 + 琥珀金（现代高级感）+ 滚动纵深漫游

## 〇、为什么推翻 v1

用户对 v1（合成波霓虹：洋红 `#e879f9` + 青 `#22d3ee` + 紫黑底 + 到处发光）的反馈：
「整体 ui 颜色配置太 ai 化，我要现代高级感」「3d 漫游效果不好，换一个形式」。

已确认的 v2 决策：

| 决策项 | 选择 |
| --- | --- |
| 配色 | **冷灰墨底 + 低饱和琥珀金**（参考 Linear / Vercel / Raycast 的暗色调性） |
| 3D 形式 | **滚动驱动的纵深穿梭**：滚轮 = 电影运镜，相机沿 Z 轴推进，图片分布在不同深度层浮现 |
| 保留 | 卡片 3D 倾斜（`v-tilt`）、路由 `neon` 转场、`immersive/dark` 开关语义 |

## 一、「AI 感」的三个来源（必须全砍）

1. **彩色发光阴影**：`box-shadow: ... 0 0 28px rgba(232,121,249,.45)` 这类霓虹光晕，全站出现 20+ 处。
2. **渐变字 / 渐变按钮**：`background-clip: text` 的洋红→青渐变品牌名、`linear-gradient(120deg, primary, dark)` 的按钮。
3. **大面积彩色 radial 光晕**：`body::before` 的 4 层彩色 radial、卡片 `::after` 的青色高光、登录卡片的青描边 + 洋红外发光。

高级感的替代：中性冷灰层次 + 单一金属色点缀（只在 hover / 选中 / 聚焦出现）+ 细腻的发丝描边 + 克制的投影（纯黑、收紧）。

## 四、3D 漫游 v2：滚动驱动纵深穿梭（重写）

**形式**：全屏层里是一条「纵深走廊」——图片按不同 X/Y/Z 散布在空间中，相机沿 +Z→-Z 匀速推进；**滚轮 = 运镜**（不再用鼠标拖拽旋转）。接近相机时图片淡入并放大（透视自带），越过相机后淡出。单击任一图打开详情。

**`src/three/neonWall.js` 重写要点**

- 布局：`items` 按索引分配到「深度层」：`z = -(index * LAYER_GAP)`（`LAYER_GAP ≈ 300`）；X/Y 用确定性散布（黄金角螺旋或按 index 取模的固定偏移），避免重叠且观感有秩序。
- 相机：`camera.position.z = travel`，`travel` 缓动追 `targetTravel`（系数 0.08）。滚轮：`targetTravel += deltaY * 1.6`，夹在 `[0, maxTravel]`。
- 逐帧：对每个 mesh 算 `d = mesh.z - camera.z`；`opacity = 进入淡入（d 从 -2200 → -900 由 0→1）× 越过淡出（d 从 -260 → +240 由 1→0）`；`transparent: true`。超出 `[-2600, +400]` 窗口的 mesh 保持 `visible = false`，跳过（省 draw call）。
- 纹理：**只在窗口内的 mesh 加载纹理**（并发上限 4），离开窗口 `texture.dispose()` 并从 Map 移除 → 天然满足「只对相机附近约 40 张真正加载」。未加载时用 `dominant_color` 纯色占位。
- 渲染：`colorSpace = SRGBColorSpace`；`setPixelRatio(min(dpr, 2))`；`antialias` 仅 `dpr <= 1.5` 开。
- 交互：`pointerup` 且位移 < 6px 视为单击 → `Raycaster` 拾取 → `onPick(id)`。还有 `onProgress(0..1, index, total)` 回调驱动底部进度条。
- 停播：`visibilitychange` / 卸载时 `cancelAnimationFrame`；`dispose()` 释放全部 texture / material / geometry / renderer 并 `forceContextLoss()`。
- 降级：能力探测（`pointer: coarse` / `hardwareConcurrency <= 4` / 无 webgl）不通过 → `onFallback()`，前台退回 CSS 悬浮墙；`webglcontextlost` 同样回退。

**`src/components/three/NeonImageWall.vue`**：壳子保留，顶栏文案改「滚动推进 · 单击打开作品」+ 底部一条极细的深度进度条（金色 1px）；背景改纯 `$color-bg-page`。仍走 `defineAsyncComponent` + 内部动态 `import('three')`，首屏不加载 three。

**`views/HomeView.vue`**：入口按钮只换色（中性 + 金 hover），其余逻辑（`roaming` / `openPhoto` / 空闲预热壳子 chunk）保持不变。

## 六、第三轮：零操作自动播放

用户反馈「我希望的是我不用操作也会有很炫酷的效果」——原来的走廊必须滚轮才动、还要点按钮才进入，等于没操作时画面是死的。本轮把「要不要动」的决定权从用户手里拿回来。

**`neonWall.js` 改动**

- **自动运镜**：`targetTravel += AUTO_SPEED * dt`（`AUTO_SPEED ≈ 110` 世界单位/秒，约 2.7 秒过一层图）。`lastInputAt` 初值 `-Infinity`，所以一进画面立刻开始推进；滚轮只是「加速器」，停手 `IDLE_RESUME_MS = 1400ms` 后自动恢复匀速。
- **无限循环**：mesh 越过相机（`d > VISIBLE_NEAR`）时 `mesh.position.z = camZ + VISIBLE_FAR - RECYCLE_MARGIN`，送回走廊最远端复位 → 走廊不会走空。
- **呼吸感**：每张图按 `travel` 做低频正弦浮动与微倾（`FLOAT_X/Y/TILT`），各自挂固定相位避免整排同步晃。
- **handheld 相机**：`camera.position.x/y` 与 `rotation.z` 按 `travel` 做极弱正弦摇摆 + 荷兰角，画面不像轨道车。
- **新增 API**：`pause() / resume()`；`IntersectionObserver` 监听容器，滚出视口即停 rAF；`supportsWebGL()` 的核数门槛从 `<= 4` 放宽到 `<= 2`（常驻自动播放要更保守，但别把四核笔记本一刀切掉）。
- **`captureWheel` / `autoAdvance` 开关**：内嵌模式必须 `captureWheel: false`，否则首页滚不动。

**`NeonImageWall.vue` 改动**：新增 `inline`（内嵌：不 teleport、不接滚轮、不显示顶栏与进度条）与 `paused`（外部要求暂停）两个 prop，以及 `fallback` 事件。顶栏文案改「自动穿梭 · 滚轮加速 · 单击打开作品」。

**`HomeView.vue` 改动**：hero 内嵌 3D——先铺 CSS 悬浮墙（零成本、立刻可见），`requestIdleCallback` 里先 `import('@/three/neonWall.js')` 探测 `supportsWebGL()`，通过且 `wall3dItems` 有数据才把 `hero3d = true`，3D 层在悬浮墙之上淡入接管；失败则 `@fallback` 退回 CSS 悬浮墙。`.hero__enter` 加 `z-index: 3` 压在内嵌 3D 层（`z-index: 2`）之上。

**本轮验收**：`npm run build` 通过（`three` 仍独立 736 kB，首屏 `index` 67 kB）；浏览器实测——hero 1201×520 内嵌 canvas 存在，**未做任何操作、两张间隔 1.5s 的截图图片位置明显变化（确实自动在动）**，控制台零报错；网格点扫描命中并跳转 `/photo/14`；右下角按钮 `z-index: 3` 有效，点击后出现 `.neon-wall--full` 全屏漫游层。

## 七、第四轮：3D 铺到全站

用户要求「把 3D 效果应用到整个项目，不只是首页」。做法不是给每个页面各挂一份场景（那会开出十几个 WebGL 上下文），而是**在 App 根上挂唯一一层环境底**，所有路由共用。

**新组件 `src/components/three/AmbientScene.vue`**

- 结构：`.ambient3d`（`position: fixed; inset: 0; z-index: -1; pointer-events: none`）+ `.ambient3d__stage`（canvas 挂点）。
- 场景参数：`pickable: false`（一个指针监听都不挂）、`captureWheel: false`、`autoSpeed: 42`（比首页慢一半多，背景不该抢戏）、`dprCap: 1.5`；只取 20 张热门图（走廊是循环回收的，再多只多占显存）。
- 亮度按路由 meta `ambientDim` 给：内页 0.28 / 上传 0.25 / 个人中心 0.22 / 后台 0.15 / 详情 0.16 / 登录注册 0.34；CSS 变量 `--ambient-dim` + `transition: opacity .6s`，切页不闪。
- 数据：模块级 `itemsPromise` 缓存，全站只请求一次热门图。
- 降级：WebGL 不可用 / 场景代码加载失败 → 异步加载原来的 CSS 照片墙 `AmbientWall.vue`；`prefers-reduced-motion` 时保留纵深构图但停住镜头。

**`neonWall.js`**：新增 `autoSpeed` / `pickable` / `dprCap` 三个 option，其余行为不变（首页与全屏漫游继续用默认值）。

**`App.vue`**：`<AmbientScene v-if="route.meta.ambient !== false" />`，挂在 router-view 之前。

**`DefaultLayout.vue`**：删掉自己那份 AmbientWall 与取图逻辑（已上移到 App）；`.layout--dark` 的实色底改 `transparent`，让详情页也能透出环境底。

**`LoginView.vue` / `RegisterView.vue`**：删掉各自的 DriftWall 背景与取图逻辑，`.auth` 底色改 `transparent`，只保留 `.auth__scrim` 压暗 —— 玻璃卡片后面现在是会动的 3D 走廊。

**路由**：`home` 保持 `ambient: false`（自带 hero 3D，避免同一批图铺两遍），其余路由补 `ambientDim`；`/admin` 在父路由上设 0.15。

**本轮验收**：`npm run build` 通过（`index` 64.48 kB，`three` 仍独立）。浏览器实测：首页 `hasAmbient=false / hasHeroWall=true`；`/search`、`/login`、`/photo/14`、`/photo/13` 均 `hasAmbient=true`、`canvasCount=1`、canvas 尺寸接近视口，**间隔 1.5s 截图背景位置变化（自动在动）**；`/search` 用滚轮滚动 `window.scrollY > 0`（环境底没吞滚轮）；详情页 `stageOpacity=0.16`，主图 444×592 正常、标题与元信息清晰可读；控制台无 three/WebGL/Vue 报错。
