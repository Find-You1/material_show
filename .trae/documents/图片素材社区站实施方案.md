# 对标 Pexels 的图片素材社区站 — 实施方案

## Context

`d:\material_show` 当前是**完全空的目录**，本方案从零搭建一个对标 Pexels 的图片素材社区网站。

用户已确认的产品与技术要求：

| 决策项 | 结论 |
|---|---|
| 技术栈 | 后端 FastAPI（Python 3.10.11）+ 前端 Vue 3 + Element Plus + Vite |
| 数据库 | MySQL 8（本机 `MySQL80` 服务运行中，8.0.45，端口 3306） |
| 产品范围 | 完整社区闭环：浏览端 + 用户体系 + 创作者上传 + 审核后台 |
| 内容模型 | 注册用户即可上传；**先审后发**；审核通过的用户图片与管理员的图片**都进公共区**，所有人可见 |
| 图片存储 | 本地磁盘 + S3(MinIO) **两套适配器都写**，配置项切换，默认本地 |
| 搜索 | MySQL 8 内置 ngram 全文索引，不引 Elasticsearch |
| UI 风格 | 专业简洁、无 AI 味图标、紧凑布局、信息层次清晰、卡片有质感、导航栏全宽吸顶、表单比列表窄且居中、筛选词一行均匀分布 |

后端与前端为同一仓库的两个子目录，单体部署。

## 关键技术决策（含理由）

1. **同步 SQLAlchemy 2.0 + PyMySQL，路由写 `def` 而非 `async def`**。
   理由：本项目图片处理是 CPU 密集操作，async 下必须显式 `run_in_threadpool`，更容易写错；Windows 上 asyncmy 需编译工具链易失败；同步方案下 FastAPI 会把 `def` 路由自动丢进线程池（默认 40 线程），对本项目并发量完全够用。
   **铁律**：所有路由写 `def`，禁止 `async def` + 同步 `db.execute` 混写（会阻塞事件循环）。

2. **密码哈希直接用 `bcrypt`，不用 passlib**。本机 bcrypt 5.0.0，passlib 1.7.4 读取 `bcrypt.__about__` 在 5.x 直接崩。bcrypt 5.0 对 >72 字节密码**抛异常**（不再静默截断），schema 层限 `max_length=72` 且哈希前 `[:72]`（中文 UTF-8 3 字节/字，24 字即超限）。

3. **JWT 用 PyJWT**（已装 2.8.0）。注意 `sub` 必须是**字符串**。采用 7 天长效 access token，暂不做 refresh token；`is_active=0` 的封禁校验放在 `get_current_user` 里每请求查库。

4. **任务执行用进程内 `ThreadPoolExecutor` + DB 持久化状态，不用 BackgroundTasks、不用 Celery**。BackgroundTasks 长任务占线程池槽位、重启即丢；Celery 要 Redis broker，是纯负担。用 `images.process_status` 字段记账 + 应用启动时补偿扫描，实现无 Redis 的"至少一次"执行。

5. **图片多档尺寸单独建 `image_variants` 表**，不在 `images` 表堆多列 URL。尺寸档位是数据不是 schema，便于加档、部分失败重试、避免表膨胀。列表页用 `selectinload` 一次 `IN` 查询取回，性能可接受。

6. **标签名冗余进 `images.tag_text` 列参与全文索引**。这样**一个 `MATCH` 同时命中标题+描述+标签**，规避 `MATCH(...) OR t.name LIKE ...` 导致全文索引失效退化成全表扫描的事故。

7. **前端瀑布流自研绝对定位**（`useMasonry.js`）。Element Plus 无瀑布流组件；`column-count` 是列优先填充，无限滚动追加时新图全堆到第一列、顺序错乱。后端返回每张图 `width/height`，可**不等图片加载即完成布局**，彻底消除重排跳动。

### 审核状态机

```
上传/管理员发布 → [pending] ──通过──> [approved] (published_at=now, 进入公共区)
                    │  ▲                    │
          驳回(reason必填)│  │用户编辑后 resubmit    │管理员下架
                    ▼  │                    ▼
                [rejected] ──直接通过──>  is_deleted=1 (记录 takedown，可 restore)
```

- `rejected` → 用户改标题/描述/标签后 `POST /api/me/uploads/{id}/resubmit`，回 `pending` 并清 `reject_reason`。
- `approved` 不退回 pending，下架用 `is_deleted=1`（保留外链与统计）。
- **公开可见的判定抽成常量** `PUBLIC_FILTER = audit_status='approved' AND is_deleted=0 AND process_status='ready'`，所有查询复用。

### 计数维护规则

- 一律**原子 UPDATE 自增**，禁止"读出来 +1 再写回"：`values(favorites_count=Image.favorites_count + delta)`。
- 收藏/下载：写明细表与计数 ±1 在**同一事务**；重复收藏靠 `UNIQUE` + `IntegrityError` 兜底。
- 浏览量不去重；需要防刷时再加 `image_view_logs(image_id, ip_hash, view_date)` 日级去重（P5 可选）。
- `tags.image_count` / `categories.image_count` / `users.*_count` 仅在**审核通过、下架、删除**三个节点全量重算（单机数据量秒级，比增量维护可靠）。

### ngram 全文索引落地

MySQL 服务端 `ngram_token_size` 默认 **2**（本机 `my.ini` 未设置），正好适配中文。它的行为与坑：
- token 切成 2 字滑窗：`"海边日落"` → `海边/边日/日落`。
- **查询串 <2 字符匹配不到任何结果**，必须应用层 LIKE 兜底。
- **停用词的坑（2026-09-30 实测）**：ngram 会把「含停用词子串」的 bigram 整个丢掉，
  而 InnoDB 默认停用词表里有单字母 `a` 和 `i`。于是 `minio` 的 5 个 bigram
  `mi/in/ni/io` **全部含 `i`**，被整词丢弃 → 索引里一个 token 都不剩 → 搜索必然 0 条。
  实测对照：`mi`/`id`/`ik` 查不到任何行，`me`/`ed`/`do`/`ng`/`cd` 正常。
  因此 LIKE 兜底**不能只按长度判断**，必须「全文 0 命中就回落」（已按此实现）。
  根治办法（2026-09-30 已实施）：`SET GLOBAL innodb_ft_enable_stopword=OFF`，再
  DROP / 重建 `ft_images_search` 索引，并把该选项写进 `my.ini` 的 `[mysqld]` 持久化
  （`my.ini.bak-20260930` 是改动前备份）。两个坑：① `--defaults-file` 必须排在
  `mysqld` 参数首位，否则报 `unknown variable 'defaults-file=...'`；② 该变量存在
  「会话在连接时取值」的行为，改完必须让应用重建连接池（重启后端）才对新上传生效。
  实测重建后 `MATCH ... AGAINST('minio')` 得分 10.93（原先恒为 0）。
- 只读启动参数，改动需改 `my.ini` + 重启服务 + REBUILD 索引，不要运行时调整。

**Alembic 必须手写迁移**（autogenerate 对 `mysql_with_parser` 支持不稳，容易丢 `WITH PARSER` 导致中文搜不到）：
```python
def upgrade():
    op.execute("CREATE FULLTEXT INDEX ft_images_search "
               "ON images (title, description, tag_text) WITH PARSER ngram")
def downgrade():
    op.execute("DROP INDEX ft_images_search ON images")
```
并在 `alembic/env.py` 加 `include_object` 排除该索引，避免 autogenerate 反复增删。

**检索 SQL**（`services/search_service.py`）：`MATCH` 的列清单**必须与建索引列完全一致**，否则报 `ERROR 1191`。
```python
_NL_SQL = text("""
SELECT i.id, MATCH(i.title, i.description, i.tag_text)
       AGAINST (:q IN NATURAL LANGUAGE MODE) AS score
FROM images i
WHERE i.audit_status='approved' AND i.is_deleted=0 AND i.process_status='ready'
  AND MATCH(i.title, i.description, i.tag_text) AGAINST (:q IN NATURAL LANGUAGE MODE)
ORDER BY score DESC, i.favorites_count DESC, i.published_at DESC
LIMIT :limit OFFSET :offset
""")
```
- `len(q) < 2` → 走 LIKE 兜底，不报错。
- 标签筛选用 `EXISTS(SELECT 1 FROM image_tags it JOIN tags t ... WHERE t.slug IN :slugs)` 做交集过滤，走 `ix_image_tags_tag`。
- 多词默认 `NATURAL LANGUAGE MODE`（召回好）；要"全包含"改用 `IN BOOLEAN MODE` + `+token`。
- `order` 参数支持 `relevance`（默认）/`latest`/`popular`。

### 存储抽象层

`app/storage/base.py` 定义**同步**接口：
```python
class StorageBackend(ABC):
    name: str                                    # "local" | "s3"
    def save(self, key: str, data: bytes, content_type: str) -> None: ...
    def save_stream(self, key: str, fileobj: BinaryIO, content_type: str) -> None: ...
    def open(self, key: str) -> BinaryIO: ...
    def exists(self, key: str) -> bool: ...
    def delete(self, key: str) -> None: ...
    def delete_many(self, keys: Iterable[str]) -> None: ...
    def url(self, key: str, *, download_name: str | None = None) -> str: ...
```

- **LocalStorage**：`root` 下按 key 建目录；`_abs(key)` 必须断言 `root in parents` 防路径穿越。`url()` 返回**相对路径** `/media/{key}`，开发期由 Vite proxy 转发、生产期由 Nginx 转发，规避 CORS 与写死域名。
- **S3Storage**（boto3，延迟 import）：`save_stream` 用 `upload_fileobj`；`url()` 优先 `S3_PUBLIC_BASE_URL` 公开读 + 固定域名（**预签名 URL 每次不同会毁掉浏览器缓存，瀑布流性能极差**），预签名仅作私有桶开关。
- **registry**：`get_storage(name)` 单例缓存 + `url_for(backend, key)` 读老数据。**数据库只存 key，URL 现算**——所以切 `STORAGE_BACKEND=s3` 后新图走 MinIO、老图仍从本地盘正常显示，无缝共存。
- 业务层**只允许**通过 `get_storage()` 调用，禁止直接 import 具体实现。
- `/media` 静态挂载建议自定义路由用 `FileResponse` 带 `Cache-Control: public, max-age=31536000, immutable`（key 含 uuid 不会变）。

### 图片处理流水线

尺寸预设（只降不升，`target_w = min(preset_w, src_w)`）：
```python
PRESETS = [("thumb", 400, {"format": "webp", "quality": 78}),
           ("preview", 960, {"format": "webp", "quality": 82}),
           ("medium", 1600, {"format": "webp", "quality": 84})]
```
命名 `{yyyy}/{mm}/{dd}/{image_uid}/original.{ext}` + `thumb.webp` / `preview.webp` / `medium.webp`，用 uuid 目录隔离，天然避免重名覆盖。

`process_image_job(image_id, tmp_path)` 步骤：
1. 校验类型白名单（jpeg/png/webp）、大小（默认 20MB，管理员可放宽 50MB）、`Image.open(p).verify()` 后 **reopen**（verify 会让文件对象失效）。
2. 设 `Image.MAX_IMAGE_PIXELS = 80_000_000`，捕获 `Image.DecompressionBombError`。
3. `ImageOps.exif_transpose(img)` 修正方向（**不做会导致手机竖拍图宽高与实际不符，直接毁掉瀑布流布局**）；提取 EXIF（`exif.get_ifd(0x8769)` 取相机/ISO/光圈/快门）。
4. 主色：`img.convert("RGB").resize((1,1), BOX).getpixel((0,0))` → `#rrggbb`。
5. 各档：JPEG 先 `img.draft("RGB", (w, h))` 触发 DCT 缩放解码加速，再 `img.thumbnail(..., Image.Resampling.LANCZOS)`（**Pillow 10 已删 `Image.ANTIALIAS`**），存 WEBP。
6. 写 `image_variants` + 更新 `images` 属性 + `process_status='ready'`；`source=='official'` 时同时 `audit_status='approved'`。
7. 失败置 `process_status='failed'` + `process_error`，前端提供"重新处理"。

内存控制：三档顺序处理、每档 `del` + `gc.collect()`、线程池 `max_workers=2`、像素上限、原图不重编码直接落盘。

**执行方式**（`app/tasks/runner.py`）：`ThreadPoolExecutor(max_workers=2)` 单例，`lifespan` 里注册 shutdown。两条铁律：
- **worker 线程内第一行就 `with SessionLocal() as db:` 自建会话**，绝不复用请求线程的 session（这是这类项目 90% 诡异 bug 的来源）。
- **启动时补偿扫描**：`UPDATE images SET process_status='queued' WHERE process_status='processing'`，再把所有 `queued` 重新 submit。

上传接口只做：校验元信息 → `save_stream` 落原图 → 建记录（`queued` + `pending`）→ `runner.submit(...)` → 立即返回 `{id, process_status}`。前端轮询 `GET /api/me/uploads/{id}` 直到 `ready`。同步路由里用 `file.file` 取底层对象喂给 `save_stream`，**不要 `await file.read()`**。

### 鉴权

```python
def hash_password(pw: str) -> str:
    return bcrypt.hashpw(pw.encode("utf-8")[:72], bcrypt.gensalt(rounds=12)).decode()
def create_access_token(user_id: int, role: str) -> str:
    now = datetime.now(timezone.utc)
    return jwt.encode({"sub": str(user_id), "role": role, "typ": "access",
                       "iat": now, "exp": now + timedelta(days=7)},
                      settings.SECRET_KEY, algorithm="HS256")
```
依赖注入：`get_db` / `get_current_user`（校验 token → 查库 → 检查 `is_active`）/ `get_current_admin`（校验 role）/ `get_optional_user`（详情页游客可看、登录可看收藏态）。
全局 `AppError` + `exception_handler` 统一返回 `{"code": "...", "message": "..."}`，前端按 `code` 处理。
`.env` 的 `SECRET_KEY` 用 `secrets.token_urlsafe(48)` 生成，**代码里禁止默认值兜底**，未设置直接 raise。

### 后端启动与配置

`scripts/init_db.sql`（以 root 执行一次）：建 `material_show` 库（`utf8mb4_0900_ai_ci`）+ 建 `ms_app` 用户授权。
**必须装 `cryptography`**：MySQL 8 默认 `caching_sha2_password`，PyMySQL 非 SSL 连接缺它会报 `RuntimeError: 'cryptography' package is required...`。

`session.py`：
```python
engine = create_engine(settings.DATABASE_URL,   # mysql+pymysql://...?charset=utf8mb4
    pool_pre_ping=True,      # 关键：不设会偶发 "MySQL server has gone away"
    pool_recycle=280, pool_size=10, max_overflow=20, future=True)
SessionLocal = sessionmaker(engine, autoflush=False, expire_on_commit=False)
```
`expire_on_commit=False` 很重要，否则 commit 后序列化 ORM 对象会触发额外 N+1 查询。

启动命令（**Windows 上 uvicorn 不要开 `--workers`**）：
```powershell
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```
CORS：开发期有 Vite proxy 其实同源，仍显式配置 `allow_origins=["http://127.0.0.1:5173","http://localhost:5173"]`、`allow_credentials=False`（用 Bearer header，设 True 与 `*` 冲突）、`expose_headers=["Content-Disposition"]`（下载原图要读文件名）。

**不给 MySQL 写 docker-compose**（本机 3306 已在跑，再起容器要换端口、多套密码，收益为零）。Docker 只用于 P5 的 MinIO。

### 瀑布流（无跳动）

`useMasonry.js`：`ResizeObserver` 监听容器宽度 → 计算列数 `floor((W+gap)/(colMin+gap))` 与列宽 → 按每张图 `height/width` 比例预算高度 → 贪心放到当前最矮列，输出 `{left, top, width, height}`。容器 `position:relative`，子项 `position:absolute` + `transition: top/left .25s`。
**关键**：直接用后端返回的 `width/height` 预算布局，不等图片加载，从根上消除重排跳动。图片未加载完用 `dominant_color` 做底色 + 骨架闪光。`useInfiniteScroll.js` 用 `IntersectionObserver` 观察底部哨兵追加下一页，新图位置由同一套计算得出、不重排已有项。

### API 层与主题

`api/http.js`：axios 实例 `baseURL:"/api"`；请求拦截器注入 `Bearer` token；响应拦截器直接返回 `res.data`，401 → 清 token 跳登录（带 redirect），其他错误 `ElMessage.error`（支持 `config.silent` 静默）。后端分页统一 `{items, total, page, size}`。

Element Plus 主题走 **CSS 变量覆盖**（零构建负担，避免 SCSS `additionalData` 与 ESM sass 的坑）：
```scss
:root {
  --el-color-primary: #2563eb;
  --el-border-radius-base: 8px;
  --el-font-size-base: 13px;      /* 紧凑 */
  --el-component-size: 34px;
  --el-text-color-primary: #0f172a;
  --el-text-color-secondary: #94a3b8;
  --el-border-color: #e6e8eb;
}
```
`tokens.scss` 补 `--shadow-card: 0 1px 3px rgba(15,23,42,.06), 0 8px 24px -8px rgba(15,23,42,.12)`、`--shadow-hover: 0 8px 28px -6px rgba(15,23,42,.18)`。

UI 硬要求落地：
- **导航栏**：`position:sticky; top:0; height:56px; width:100%`，前台 `DefaultLayout` 与后台 `AdminLayout` **共用同一个 `AppNavbar` 组件实例**保证各页一致。白底 + 1px 底边框 + 极轻阴影，**不用红色渐变**。
- **卡片质感**：`ImageCard` 圆角 12px + `--shadow-card`，hover 时 `translateY(-2px)` + `--shadow-hover` + 图片 `scale(1.03)`，底部信息条 `linear-gradient(to top, rgba(15,23,42,.55), transparent)`。
- **信息层次**：抽 `StatNumber.vue`——数值 `600/15px/主色`，说明文字 `12px/次要色`，下载/收藏/浏览复用。
- **筛选词一行均匀分布**：`FilterBar` 用 `display:grid; grid-template-columns: repeat(auto-fit, minmax(150px, 1fr)); gap:12px`。**禁用 `flex + justify-content:flex-start`**。
- **表单单列窄且居中**：`.form-narrow{max-width:520px;margin-inline:auto}`（上传页 640px），`.list-wide{max-width:1200px;margin-inline:auto}`。后台驳回弹窗 420px、`label-position="top"`。
- **不用 AI 味图标**：只用 `@element-plus/icons-vue` 的功能性图标（搜索/上传/下载/筛选/关闭），导航优先纯文字，不用渐变发光的机器人形象。

## 四、验证方式

**P0**：`alembic upgrade head` → 连 MySQL 执行 `SHOW TABLES;` 与 `SHOW INDEX FROM images;`，确认 `ft_images_search` 的 `Index_type=FULLTEXT` 且带 ngram parser；`curl http://127.0.0.1:8000/health` 返回 200。

**P1**：`curl -X POST /api/auth/register` 建号 → 登录拿 token → 带 token 请求 `/api/me` 返回用户信息；不带 token 返回 401；用普通用户 token 请求 `/api/admin/audit` 返回 403。前端浏览器验证刷新保持登录态。

**P2**：后台上传一张 4000×3000 JPEG，检查：磁盘四档文件存在、`image_variants` 4 行、`SELECT width,height,dominant_color,process_status FROM images` 正确、浏览器 `<img src="/media/...">` 能出图。

**P3**：造 30 条 approved 数据，浏览器验证首页三列瀑布流、滚动加载、窗口缩放列数变化平滑；执行 `SELECT id, MATCH(title,description,tag_text) AGAINST ('海边' IN NATURAL LANGUAGE MODE) FROM images` 确认有非零 score；搜单字"海"不报错；搜多字命中标签来源。

**P4**：用户上传 → 首页搜不到 → 管理员后台通过 → 首页立刻可见且可搜到 → 驳回另一张并写原因 → 用户后台看到驳回原因 → 改后重提回 pending。查 `audit_logs` 记录完整。

**P5**：`docker compose up -d minio` → 改 `.env` 为 `STORAGE_BACKEND=s3` → 重启后端 → 上传新图确认落在 MinIO 且前端正常显示，同时**刷新老图页面确认仍从本地盘显示**；改回 local 再上传确认回本地。

**P6**：`npm run build` 产出 `dist/`，由后端静态托管，浏览器全站走一遍无控制台报错。

## 五、必须避开的踩坑清单

1. **禁止 `async def` 路由 + 同步 `db.execute` 混写** —— 会阻塞事件循环，比全同步慢一个数量级。
2. **passlib 与 bcrypt 5.x 不兼容**（读 `__about__` 直接崩）；bcrypt 5.0 对 >72 字节密码**抛异常**而非截断。
3. **PyJWT `sub` 必须是字符串**；用 `datetime.now(timezone.utc)`，不用 `utcnow()`。
4. **PyMySQL 连 MySQL 8 必须装 `cryptography`**，否则 `caching_sha2_password` 认证直接 RuntimeError。
5. **`MATCH` 列清单必须与建索引列完全一致**，否则 `ERROR 1191`；`mysql_with_parser` 必须手写迁移 + `include_object` 排除。
6. **`ngram_token_size=2` 下单字查询必然 0 结果**，必须 LIKE 兜底。
7. **禁止 `MATCH(...) OR t.name LIKE ...`** —— 会让全文索引失效退化成全表扫描；本方案用 `tag_text` 冗余列规避。
8. **Pillow**：必须设 `MAX_IMAGE_PIXELS`；`verify()` 后需 reopen；Pillow 10 已删 `ANTIALIAS`；漏掉 `exif_transpose` 会让竖拍图宽高错位毁掉瀑布流。
9. **Element Plus 无瀑布流组件**：不用 `column-count`（列优先导致无限滚动顺序错乱）。
10. **BackgroundTasks 不是任务队列**：用 ThreadPoolExecutor + `process_status` 持久化 + 启动补偿扫描。
11. **不要跨线程复用 SQLAlchemy Session**；worker 内自建 `SessionLocal()`。
12. **Vite proxy 漏配 `/media`** 导致本地图片全 404。
13. **S3 预签名 URL 会毁掉浏览器缓存**，公开资源用公开读 + 固定域名。
14. **Windows 上 uvicorn 不开 `--workers`**；`--reload` 会打断处理任务，靠启动补偿扫回来。
15. **CORS `allow_credentials=True` 与 `allow_origins=["*"]` 互斥**；本项目用 Bearer header，设 `False`。
